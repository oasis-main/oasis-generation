# Oasis capability token, contract v1 (ORG-171 step 1)

Status: draft for Claude Code review. No service code in this PR. The executable
form of this page is `scripts/capability_token_ref.py`; the shared test data is
`vectors.json` (50 token vectors, 12 billing vectors, 29 `oasis-ws` vectors, regenerated by
`python scripts/capability_token_ref.py`, checked by `tests/test_capability_token_contract.py`).
Step 2 (`oasis-cloud src/shared/capability_token.py`), step 3 (oasis-auth issuer) and
the gateway (step 5) must each reproduce every vector's decision and reason code.

Decided 2026-10-23: Ed25519 (EdDSA), JWKS endpoint in oasis-auth,
lifetime <= 15 min, local verification with a cached JWKS, revocation on
`oasis/system/auth/revocation`.

## 1. Format

Compact JWS, three base64url segments, no padding.

Decoding is strict, so one token has exactly one string form (a token string may be a
cache or log key). Each segment must match `^[A-Za-z0-9_-]+$` (no `=`, no `+`, no `/`,
no whitespace), and its decoded bytes must re-encode to the same text (this refuses
non-canonical trailing bits). Header and payload JSON must not repeat a key: a verifier
that keeps the first value and one that keeps the last would otherwise disagree on
`kid`, `tier` or `scopes`. Any of these is `malformed`.

Header: `{"alg":"EdDSA","typ":"oasis-cap+jwt","kid":"<key id>"}`.
The verifier accepts exactly `alg=EdDSA` and `typ=oasis-cap+jwt`. It never reads the
key type from the token. `none`, `HS*`, `ES*`, `RS*` are rejected (`bad_alg`).

## 2. Claims

| Claim | Type | Rule |
|---|---|---|
| `iss` | string | exactly `https://auth.<env>.cloud.oasis-x.io` (config per env; the vectors use the dev value) |
| `aud` | string | exactly `oasis-gen` for the gateway, exactly `oasis-ws` for the workspace MCP server (section 9). A list is refused. |
| `sub` | string, non-empty | the oasis-auth user id |
| `tier` | `free` `personal` `pro` `max` | ORG-172 section 10 |
| `billing_state` | `none` `active` `suspended` | `active` means a card is on file and billing is on |
| `scopes` | string[] | known: `gen:chat gen:models gen:decide ws:session ws:fs ws:shell`. Unknown scopes are carried, never granted. |
| `allowance_ref` | non-empty string | reference to the remaining spend allowance (not the amount). Required for a metered call; empty, null or any other type gives 402. |
| `jti` | string, non-empty | unique per token; the revocation key |
| `iat`, `exp` | integers (seconds) | `0 < exp - iat <= 900`. Floats are `malformed`. `exp <= iat` is `bad_lifetime`; `exp - iat > 900` is `lifetime_too_long`. |
| `ws` | string[] (optional) | workspace session ids. Optional for `oasis-gen`. **Required and non-empty for `oasis-ws`** (section 9). If present it must be a list of strings, else `malformed`. |

Clock leeway: 30 s (expired only when `now >= exp + 30`; not yet valid when `iat > now + 30`).

## 3. Keys

`GET <iss>/.well-known/jwks.json` returns OKP / Ed25519 keys with `kid`. Verifiers
cache the set (TTL 10 min) and refetch once, rate-limited, on an unknown `kid`. The
private key lives in a KMS or Secrets Manager entry owned by the infrastructure Terraform; no
code in this repo reads it. Rotation: publish the new key in the JWKS first, sign with
it a full token lifetime later, remove the old key a full lifetime after that.

## 4. Reject codes (stable, tested)

`malformed bad_alg bad_typ unknown_kid bad_signature missing_claim bad_iss bad_aud
lifetime_too_long bad_lifetime expired not_yet_valid bad_tier bad_billing_state revoked bad_session missing_scope`.
(`bad_session` applies to `aud=oasis-ws` only, section 9.)
Order of checks is fixed: structure, alg, typ, key, signature, then claims, then
revocation, then (workspace only) session, then scope. Nothing about a claim is trusted before the signature checks out.

## 5. Gateway decision after a valid token (ORG-172 rule 2)

| Token | Metered route (chat, decide) |
|---|---|
| `billing_state=suspended` | 403 `account_suspended` |
| `tier=free`, or `billing_state != active`, or `allowance_ref` missing, empty or not a string | 402 `payment_required` |
| otherwise | allowed |

`GET /v1/models` needs only a valid token with `gen:models`; free tier may list models.
Allowance exhausted: 429 `spend_cap_reached` (hard stop, ORG-172 10.5).

## 6. Revocation

oasis-auth publishes `{jti|sub, reason, ts}` on `oasis/system/auth/revocation`. The
gateway keeps a revoked-jti set and a per-`sub` "not before" time, both held until
`exp + leeway` of the longest-lived token. If the gateway cannot reach the broker it
keeps serving on the last set, and the short lifetime bounds the exposure to 15 min.

Reference rule for the per-`sub` time: `verify(..., not_before_by_sub={sub: t})` refuses a
token as `revoked` when `iat < t` for its `sub` (`iat == t` is accepted). The check runs
right after the `jti` check. Steps 2 and the gateway must implement exactly this.

## 7. Not in this contract

Refresh flow (oasis-auth issues a new token from the Firebase session), Stripe,
price table, usage events (step 6). Workspace (MCP) tokens are section 9.

## 8. Known limits

- A test seed is committed on purpose. The JWKS in `vectors.json` is never a trust root.
- Vectors prove the reference verifier and the decision table agree with this text.
  They do not prove the issuer signs correct claims; step 3 needs its own tests.

## 9. Workspace tokens, audience `oasis-ws` (ORG-170 P1, step 1)

Decided 2026-11-05: oasis-auth mints the workspace token
(`POST /capability/token` with the `oasis-ws` audience and a session id); the workspace
manager does not hold the signing key; in P1 the token stays on the server side and never
reaches the browser. Same format, keys, lifetime (<= 900 s), leeway and revocation as
sections 1-6. What differs:

| Rule | `oasis-gen` | `oasis-ws` |
|---|---|---|
| `aud` | `oasis-gen` | `oasis-ws` (a gateway token never opens a workspace, and the reverse) |
| `ws` claim | optional | **required, non-empty list of session ids**. Missing or empty is `missing_claim`; wrong type is `malformed`. |
| session binding | none | the MCP server passes its own `SESSION_ID`; the token's `ws` must contain it **exactly** (no prefix, no case folding, no empty id), else `bad_session` |
| billing / tier | section 5 | not decided by the verifier. The manager refuses to create a session for a free tier (ORG-172); the token only proves identity, audience, session and scope. |

Scope per MCP tool (a tool not in this table is refused by the server, never defaulted):

| Tool | Scope |
|---|---|
| `ws_info`, `ws_stop` | `ws:session` |
| `fs_list`, `fs_read`, `fs_write`, `fs_patch`, `fs_search`, `fs_stat`, `fs_move`, `fs_delete` | `ws:fs` |
| `shell_exec`, `shell_start`, `shell_read`, `shell_stop` | `ws:shell` |

The server verifies on **every** request, not once per connection (tokens live <= 15 min and
revocation is by `jti` and per-`sub` not-before). It subscribes to nothing: the manager
holds the broker connection and stops the task on revocation of the session's `sub`
(plan F4). The in-box audit lines (command hash, exit code) are advisory and never used for
billing (plan F3, accepted): compute is billed from ECS `startedAt`/`stoppedAt`.

The 29 `ws_token_vectors` in `vectors.json` cover: audience separation both ways, list and
prefixed audiences, session match / mismatch / prefix / case / empty, missing, empty and
ill-typed `ws`, scope table gaps (including gateway scopes not granting `ws:*`), the shared
checks under this audience, and check order (revocation before session before scope).
A payload swapped after signing to target another session is `bad_signature`.
